# 批量入仓新增任务发布成功判断

## 规则说明

判断批量入仓-新增任务流程中，上传的测试表是否已完全发布成功到入仓系统，包括数据源配置、抽数节点配置、调度配置和流程实例的完整创建。

**判断依据**:
1. 在 `dataops_extract_input_datasource_config_info` 表中存在对应的数据源配置记录（根据 table_name、instance_name、db_name 匹配）。
2. 通过表关联关系，验证 `dataops_extract_node_config_info`、`dataops_task_schedule_config_info`、`dataops_process_instance_info` 各表都已生成对应记录。
3. 最终以 `dataops_process_instance_info.status = 0` 为发布成功的最终标志。

---

## 表关联关系

```
dataops_extract_input_datasource_config_info (TKD_008)
  ↓ (通过 id = extract_input_datasource_config_id)
dataops_extract_node_config_info (TKD_007)
  ↓ (通过 extract_schedule_config_id = id)
dataops_task_schedule_config_info (TKD_009)

dataops_extract_node_config_info (TKD_007)
  ↓ (通过 id = process_business_id)
dataops_process_instance_info (TKD_006)
```

---

## 验证方法

### 步骤 1: 查询数据源配置记录

根据批量上传文件中的表信息，在数据源配置表中查找对应记录：

```sql
-- 查询数据源配置 (TKD_008)
SELECT id AS datasource_config_id,
       instance_name,
       db_name,
       table_name,
       status,
       etlx_datasource
FROM dataops_extract_input_datasource_config_info
WHERE table_name = '${批量文件中的表名}'
  AND instance_name = '${批量文件中的实例名}'
  AND db_name = '${批量文件中的数据库名}'
  AND status = 0;  -- 0=正常状态
```

**预期结果**:
- 查询到 1 条记录
- `status = 0` (正常状态)
- 记录 `datasource_config_id` 用于后续关联查询

---

### 步骤 2: 查询抽数节点配置记录

通过数据源配置ID，查询关联的抽数节点配置：

```sql
-- 查询抽数节点配置 (TKD_007)
SELECT id AS node_config_id,
       extract_input_datasource_config_id,
       extract_schedule_config_id,
       extract_method,
       deal_method,
       target_table_name,
       output_table_name
FROM dataops_extract_node_config_info
WHERE extract_input_datasource_config_id = ${datasource_config_id};
```

**预期结果**:
- 查询到 1 条记录
- `extract_method` 与批量文件中的"抽数方式"一致（ins=增量，all=全量）
- `deal_method` 与批量文件中的"处理方式"一致（merge=合并，all=覆盖，ins=分区）
- 记录 `node_config_id` 和 `extract_schedule_config_id` 用于后续关联查询

---

### 步骤 3: 查询任务调度配置记录

通过调度配置ID，查询调度配置：

```sql
-- 查询任务调度配置 (TKD_009)
SELECT id,
       scheduling_cycle,
       scheduling_time,
       stop_scheduling,
       cpus,
       mem
FROM dataops_task_schedule_config_info
WHERE id = ${extract_schedule_config_id};
```

**预期结果**:
- 查询到 1 条记录
- `scheduling_cycle` 与批量文件中的"调度周期"一致
- `scheduling_time` 与批量文件中的"调度时间"一致
- `cpus` 与批量文件中的"CPU"一致
- `mem` 与批量文件中的"内存"一致

---

### 步骤 4: 查询流程实例记录（最终判断）

通过抽数节点配置ID，查询流程实例状态：

```sql
-- 查询流程实例 (TKD_006) - 最终判断标志
SELECT id AS process_instance_id,
       process_business_id,
       status,
       start_time,
       end_time,
       user_journey
FROM dataops_process_instance_info
WHERE process_business_id = ${node_config_id};
```

**预期结果**:
- 查询到至少 1 条记录
- `status = 0` **(发布成功的最终标志)**
- `process_business_id` 等于抽数节点配置ID

## 完整验证SQL

```sql
-- 完整关联查询 - 一次性验证所有表
SELECT
    ds.id AS datasource_config_id,
    ds.table_name,
    ds.instance_name,
    ds.db_name,
    ds.status AS datasource_status,

    node.id AS node_config_id,
    node.extract_method,
    node.deal_method,

    sch.id AS schedule_config_id,
    sch.scheduling_cycle,
    sch.scheduling_time,

    pi.id AS process_instance_id,
    pi.status AS process_status,
    pi.start_time,
    pi.end_time

FROM dataops_extract_input_datasource_config_info ds
INNER JOIN dataops_extract_node_config_info node
    ON ds.id = node.extract_input_datasource_config_id
INNER JOIN dataops_task_schedule_config_info sch
    ON node.extract_schedule_config_id = sch.id
LEFT JOIN dataops_process_instance_info pi
    ON node.id = pi.process_business_id

WHERE ds.table_name = '${批量文件中的表名}'
  AND ds.instance_name = '${批量文件中的实例名}'
  AND ds.db_name = '${批量文件中的数据库名}'
  AND ds.status = 0;
```

**成功判断条件**:
```yaml
- record_exists: true                           # 查询到记录
- field_equals: {field: "datasource_status", expected: 0}  # 数据源状态正常
- field_not_null: {field: "node_config_id"}     # 抽数节点已创建
- field_not_null: {field: "schedule_config_id"} # 调度配置已创建
- field_not_null: {field: "process_instance_id"}# 流程实例已创建
- field_equals: {field: "process_status", expected: 0}     # 流程状态为发布成功
```

## 失败场景判断

### 场景 1: 数据源配置未创建

```sql
-- 查询结果为空
SELECT COUNT(*) FROM dataops_extract_input_datasource_config_info
WHERE table_name = '${table}' AND instance_name = '${instance}' AND db_name = '${db}';
-- 结果: 0 (失败)
```

**原因**: 元数据未完善或批量任务发布失败

---

### 场景 2: 抽数节点配置缺失

```sql
-- 查询到数据源配置，但关联不到抽数节点
SELECT node.id FROM dataops_extract_input_datasource_config_info ds
LEFT JOIN dataops_extract_node_config_info node ON ds.id = node.extract_input_datasource_config_id
WHERE ds.id = ${datasource_config_id};
-- node.id 为 NULL (失败)
```

**原因**: 批量任务发布流程中断，未生成抽数节点配置

---

### 场景 3: 流程实例状态异常

```sql
-- 查询到流程实例，但状态不为 0
SELECT status FROM dataops_process_instance_info
WHERE process_business_id = ${node_config_id};
-- status != 0 (失败)
```

**原因**: 任务发布未完成或处于异常状态

## 关键知识点

- **完整性验证**: 必须验证 4 张表（TKD_006/007/008/009）都已生成记录，缺一不可。
- **最终判断标志**: `dataops_process_instance_info.status = 0` 是发布成功的唯一权威标志。
- **关联查询顺序**: 从数据源配置表(TKD_008)开始 → 抽数节点(TKD_007) → 调度配置(TKD_009) + 流程实例(TKD_006)。
- **表名匹配规则**: 必须同时匹配 table_name、instance_name、db_name 三个字段，避免重名表误判。
- **状态字段差异**:
  - TKD_008.status: 0=正常，1=已删除
  - TKD_006.status: 0=发布成功（特殊状态）
- **时间验证**: 可通过 `created_at` 或 `updated_at` 字段验证记录生成时间是否在批量任务提交之后。
