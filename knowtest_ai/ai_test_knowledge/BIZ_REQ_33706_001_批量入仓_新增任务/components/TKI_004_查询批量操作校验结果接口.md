# 查询批量操作校验结果

## 基础信息
| 属性 | 值                                           |
|------|---------------------------------------------|
| 所属应用 | dataops                                     |
| 调用服务 | /dataops/etlx/batch/v2/task/{taskId}/result |
| 请求方法  | GET                                         | 
| 服务提供方 | DataOps                                     |
| 测试方式 | 真实环境测试（非Mock）                               |

## 调用参数

### taskId（任务ID）
- **来源**: [TKI_003].response.data.taskId
- **格式**: 路径参数 (Path Parameter)
- **说明**: 引用批量上传接口返回的唯一任务标识。

### HTTP Header（请求头）
- **p_n**: 创建人姓名，固定值 `施婷杰`
- **p_u**: 创建人UID，固定值 `71e8b23d-45e2-497a-b247-f5b807fb4f65`
- **说明**: 接口通过 HTTP Header 识别 CreatedBy 和 CreatedUid


## 返回结果

### 结构说明
| 字段路径 | 类型 | 说明 |
|---------|------|------|
| code | Integer | 响应码（0=成功） |
| success | Boolean | 业务处理是否成功 |
| failure | Boolean | 是否失败标志 |
| message | String | 响应消息 |
| data.failedRows | Array | 校验失败的详细行记录 |
| data.failureStatistics | Object | 失败原因分类统计 |
| data.publishFailedCount | Integer | 校验未通过的任务总数 |
| data.parseFailedRows | Array | 解析失败的行记录 |

### 数据保存
- **[TKD_003].task_status**: 保存校验状态（如 VALIDATE_SUCCESS, VALIDATE_FAILED）
- **[TKD_003].error_message**: 完整保存 `$.data` 层级的 JSON 字符串

### 关键知识

- **异步结果轮询**: 该接口用于查询批量任务上传后的异步校验结果。在自动化测试中，需确保在调用 BPM 审批前，该接口已返回校验通过。
- **错误持久化机制**: 当校验不通过时，接口返回的整个 `data` 对象（包含失败行详情及原因统计）会完整记录在数据库 `dataops_batch_operation_task.error_message` 字段中。
- **业务校验规则**: 常见的校验失败逻辑包括：表注释必须包含中文且长度大于等于2个字符。此类业务规则不通过会导致任务状态置为 `VALIDATE_FAILED`。
- **链路阻断逻辑**: 校验结果是任务发布的“准入证”。若 `publishFailedCount > 0`，即使外部强行发送 BPM 审批通过消息，DataOps 后端也会因校验状态不符而拒绝执行【发布】操作。
- **数据库状态映射**: 
    - 校验通过 -> `task_status = 'VALIDATE_SUCCESS'`
    - 校验失败 -> `task_status = 'VALIDATE_FAILED'`
