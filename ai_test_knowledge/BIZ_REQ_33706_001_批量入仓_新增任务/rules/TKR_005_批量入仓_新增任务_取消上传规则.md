# 批量上传任务取消及清理状态判断

## 规则说明

用户在执行文件上传操作后，系统会在 `dataops_batch_operation_task` 表中生成一条 `task_type` 为 `UPLOAD` 的记录。根据校验结果，其 `task_status` 可能为 `VALIDATE_SUCCESS`（校验成功）或 `VALIDATE_FAILED`（校验失败）。

当用户执行“取消”操作时，服务端会根据接口请求中的 `{taskId}` 执行数据清理逻辑。本规则用于验证取消后该任务记录是否已成功从数据库中清除。

**判断依据**: 
- `dataops_batch_operation_task.id` 等于接口请求参数 `{taskId}`。
- **校验标准**：数据库中该 `taskId` 对应的记录不存在（查询结果为空）。

---

## 验证方法

```yaml
# 验证批量上传产生的临时任务（UPLOAD类型）已成功清除
- record_not_exists:
    table: "dataops.dataops_batch_operation_task"
    where: "id='${taskId}' AND task_type='UPLOAD'"
```

**SQL查询**:
```sql
-- 预期查询结果记录数为 0
SELECT COUNT(1) AS record_count
FROM dataops.dataops_batch_operation_task
WHERE id = '${taskId}'
  AND task_type = 'UPLOAD';
```

**预期结果**: 
- `record_count = 0`

---

## 测试数据准备

```yaml
# 1. 模拟取消前的初始状态（场景A：校验成功后取消）
dataops.dataops_batch_operation_task:
  - id: 386
    task_status: "VALIDATE_SUCCESS"
    task_type: "UPLOAD"

# 2. 模拟取消前的初始状态（场景B：校验失败后取消）
dataops.dataops_batch_operation_task:
  - id: 387
    task_status: "VALIDATE_FAILED"
    task_type: "UPLOAD"

# 3. 预期清理动作
# 调用取消接口后，以上 id 为 386 或 387 且 task_type='UPLOAD' 的记录应被物理删除。
```
