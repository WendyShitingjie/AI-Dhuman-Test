# 提交批量操作任务

## 基础信息
| 属性    | 值                                      |
|-------|----------------------------------------|
| 所属应用  | dataops                                |
| 调用服务  | /dataops/etlx/batch/v2/submit/{taskId} |
| 请求方法  | POST                                   | 
| 服务提供方 | DataOps                                |
| 测试方式  | 真实环境测试（非Mock）                          |

## 调用参数

### taskId（任务ID）
- **来源**: [TKI_003].response.data.taskId
- **格式**: Path Parameter / Long
- **调用前提**: 必须在 [TKI_004] 接口返回【校验通过】（即 ` [TKD_001].task_status = 'VALIDATE_SUCCESS'`）后方可调用。

### HTTP Header（请求头）
- **p_n**: 创建人姓名，固定值 `施婷杰`
- **p_u**: 创建人UID，固定值 `71e8b23d-45e2-497a-b247-f5b807fb4f65`
- **说明**: 接口通过 HTTP Header 识别 CreatedBy 和 CreatedUid

### Query Parameter（查询参数）
- **p_n**: 固定值 `施婷杰`
- **p_u**: 固定值 `71e8b23d-45e2-497a-b247-f5b807fb4f65`

## 返回结果

### 结构说明
| 字段路径    | 类型      | 说明               |
|---------|---------|------------------|
| code    | Integer | 响应码（0=成功）        |
| success | Boolean | 业务处理是否成功         |
| message | String  | 响应消息             |
| data    | String  | 提交结果描述（如：“提交成功”） |

### 数据保存
- **[TKD_001].bpm_order_no**: 保存生成的 BPM 审批工单号
- **[TKD_001].task_status**: 状态更新为 `PENDING_APPROVAL` (待审批)
- **[TKD_010].order_no**: 保存 BPM 工单号（BPM记录表）
- **[TKD_010].status**: 状态翻转为 `2` (审批中)



### 关键知识
- **前置逻辑校验**: 该接口具备强置前置条件。系统会校验 `taskId` 对应的任务是否已通过解析与业务校验。若任务在数据库中不处于 `VALIDATE_SUCCESS` 状态，提交操作将被拒绝。
- **BPM工单关联**: 提交成功标志着“JDBC批量入仓-新增任务”流程的正式启动。接口响应后，系统会生成唯一的 BPM 工单号并分别落表至 `dataops_batch_operation_task` 和 `dataops_bpm_record`。
- **数据库状态机**: 
    - 任务表状态流转：`VALIDATE_SUCCESS` -> `PENDING_APPROVAL` (待审批)。
    - BPM记录表状态：置为 `2` (审批中)。
- **审批链路衔接**: 成功提交后产生的工单号（bpm_order_no）是后续自动化测试中使用 `mq-sender` 模拟审批通过消息的核心入参。只有在该接口成功返回后，才能触发自然语言指令：“发送批量入仓-新增任务(taskId={`taskId`})的审批通过的bpm消息”。
