# 批量上传校验

## 基础信息
| 属性    | 值                               |
|-------|---------------------------------|
| 所属应用  | dataops                         |
| 调用服务  | /dataops/etlx/batch/v2/validate |
| 请求方法  | POST                            | 
| 服务提供方 | DataOps                         |
| 测试方式  | 真实环境测试（非Mock）                   |

## 调用参数

### optionType（操作类型）
- **来源**: 固定值 `UPLOAD`
- **格式**: 字符串

### taskId（任务ID）
- **来源**: [TKD_001].id
- **格式**: Long (Query Parameter)
- **说明**: 新增任务时无需传入；修改任务时由上下文变量提供。

### file（上传文件）
- **来源**: 动态匹配。由测试用例传入的 fileName 参数决定。通常是`test_data/` 目录下的测试模板文件（例如：`.xlsx` 文件）
- **完整路径算法**: project_root/test_data/{fileName}
- **格式**: Binary (Form Data)


### HTTP Header（请求头）
- **p_n**: 创建人姓名，固定值 `施婷杰`
- **p_u**: 创建人UID，固定值 `71e8b23d-45e2-497a-b247-f5b807fb4f65`
- **说明**: 接口通过 HTTP Header 识别 CreatedBy 和 CreatedUid

### Query Parameter（查询参数）
- **p_n**: 固定值 `施婷杰`
- **p_u**: 固定值 `71e8b23d-45e2-497a-b247-f5b807fb4f65`
- **说明**: 必须同时在 Query Parameter 中传递人员信息，否则会导致后续提交接口失败（CreatedBy 不能为空）

## 返回结果

### 结构说明
| 字段路径          | 类型      | 说明                                   |
|---------------|---------|--------------------------------------|
| code          | Integer | 响应码（0=成功）                            |
| success       | Boolean | 业务处理是否成功                             |
| message       | String  | 响应消息                                 |
| data.taskId   | Integer | 任务唯一标识ID，也是测试用例中${context.taskId}的来源 |
| data.fileName | String  | 上传文件名称                               |

### 数据保存
- **[TKD_001].id**: 保存返回的 `data.taskId`
- **[TKD_002].process_instance_node_id**: 映射 `data.taskId` 用于 BPM 审批流

## 测试要点

### 成功场景断言
```yaml
- field_equals: {field: "code", expected: 0}
- field_equals: {field: "success", expected: true}
- field_not_null: {field: "data.taskId"}
- field_contains: {field: "data.fileName", expected: ".xlsx"}
```
### 失败场景断言
```yaml
- field_equals: {field: "code", expected: 500}
- field_not_null: {field: "message"}
- field_equals: {field: "success", expected: false}
```

### 关键知识
- **核心标识映射**: 接口返回的 `taskId` 是整个业务链路的唯一索引。它在数据库中同时映射为 `dataops_batch_operation_task.id`（任务主键）以及 `dataops_bpm_record.process_instance_node_id`（流程节点标识）。
- **BPM 模拟触发**: 获取 `taskId` 后，可配合 `mq-sender` 工具通过自然语言（如：“帮我把 taskId={taskId} 的任务发送审批通过的消息”）模拟 BPM 审批流。
- **自动化脚本实现**: 自动化测试时，建议使用 Python 的 `requests` 库读取 `test_data` 文件夹内的 `.xlsx` 模板文件。库会自动处理 `multipart/form-data` 的 Boundary 字符串，无需手动构造。
- **业务消费逻辑**: DataOps 服务端会自动监听 MQ 消息。一旦接收到审批通过信号，系统将根据 `taskId` 检索上传的文件内容，并对其中所有的 MySQL 入仓任务执行【发布】操作。
- **前置依赖性**: 该接口是批量入仓流程的起点，其输出的 `taskId` 是后续“查询校验结果接口”和“BPM 消息推送”的必需入参。
